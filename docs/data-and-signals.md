# Контракт данных и сигналов

## Вход

Первый инструмент — BTC/USDT на Binance Spot. Цена задаётся в USDT/BTC, количество на уровне — в BTC, номинал Q — в USDT. Для расчётов использовать десятичную арифметику или целые тики и шаги количества. В манифесте записывать площадку, инструмент, UTC-интервал, источник и формат, контрольные суммы файлов, шаг цены, шаг количества и правила минимального ордера. Архивы и ключи доступа хранить вне Git.

Основной источник — исторический Tardis incremental_book_L2. Для нормализованной строки нужны время события биржи, локальное время приёма сборщиком, признак снимка, сторона, цена, абсолютный размер. Сохранять исходный порядок строк и границы обновлений. Время приёма сборщиком служит приближением к времени доступности данных стратегии. Для book_snapshot_25 каждый снимок целиком заменяет предыдущие 25 уровней; этот режим отметить в отчёте и исследовать отдельно, поскольку события между снимками неизвестны.

## Воспроизведение

1. Начинать с полного доступного снимка. Для одного пакета применить все изменения до расчёта признаков. Если источник не даёт ID пакета, документировать способ группировки, например последовательные строки одного инструмента с одинаковыми обеими метками времени и признаком снимка.
2. Дельта с положительным размером заменяет количество на данной цене, ноль удаляет уровень. Новый снимок очищает старые уровни. Лучший bid — максимальная цена покупки, лучший ask — минимальная цена продажи.
3. Проверять порядок сообщений и непрерывность последовательности там, где источник предоставляет номера. При обнаруженном разрыве, пустой стороне или пересечении bid ≥ ask помечать интервал недействительным до следующего корректного снимка. При отсутствии номеров указывать ограничение контроля пропусков. На границе файла сохранять состояние только при подтверждённой непрерывности.
4. Решение в момент t видит только пакеты с временем приёма ≤ t. События с одинаковой меткой обработать в порядке источника перед решением. Метки для будущей доходности записывать отдельным этапом. Для каждого исключения сохранять причину и длительность.

## VampIndicator и эталон L1

Для каждой стороны пройти от лучшей цены вглубь до достижения номинала Q. На уровне с ценой p и количеством v взять x = min(v, остаток_номинала / p), уменьшить остаток на p·x. При полном покрытии VWAP = Q / Σx. Индикатор измеряет виртуальную стоимость и допускает дробный последний уровень. Если одна сторона не покрывает Q, вернуть пропуск для этого Q и увеличить счётчик недостаточной глубины.

- mid = (best_bid + best_ask) / 2.
- VAMP(Q) = (VWAP_bid(Q) + VWAP_ask(Q)) / 2.
- Сигнал в базисных пунктах s = 10 000 · (VAMP / mid − 1).
- Эталон L1 = (v_bid − v_ask) / (v_bid + v_ask), где v — количества на лучших ценах. Сравнивать сигналы на общем наборе валидных наблюдений.

При положительном s виртуальная покупка отклоняется от лучшего аска сильнее, чем продажа от лучшего бида. Направление будущего изменения mid проверяет эксперимент.

## Приёмочные примеры

| Стакан (цена × количество) | Вход | Ожидание |
|---|---|---|
| bid 99 × 10, ask 101 × 1 | Q = 100 | Оба номинала помещаются на первом уровне. VAMP = mid = 100, s = 0, L1 = 9/11. |
| bid 99 × 10, asks 101 × 1 и 103 × 3 | Q = 204 | Покупка потребляет 1 единицу по 101 и 1 по 103. VWAP ask = 102, bid = 99, VAMP = 100,5, s = +50 б.п. |
| Тот же стакан после удаления уровня 103 | Q = 204 | На покупку доступно только 101 USDT. Значение VAMP отсутствует. |

Выход на каждый момент решения и Q: время UTC, идентификатор инструмента, цены и размеры L1, mid, Q, оба VWAP, s, L1, возраст последнего пакета и статус качества. Эта таблица служит общим входом для оценки прогноза и решений стратегии.
