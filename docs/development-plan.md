# План разработки

Цель первого релиза — воспроизводимый отчёт для Binance Spot BTC/USDT. По нему исследователь должен ответить на два вопроса: улучшает ли глубина стакана прогноз относительно дисбаланса лучшего уровня и можно ли получить это улучшение в сделках после издержек. Отрицательный результат тоже завершает исследование.

| Этап | Работы и зависимости | Результат и приёмка |
|---|---|---|
| 1. Образец данных | Получить один полный день исторического L2 и параметры инструмента на эту дату. Зафиксировать версии Python и Nautilus Trader, тариф комиссий и источник данных. | Манифест позволяет идентифицировать каждый входной файл. Измерены место на диске, пиковая память и время обработки дня. |
| 2. Восстановление стакана | После этапа 1 преобразовать сообщения в события Nautilus Trader. Сохранять порядок пакетов и границы снимков. | Контрольный поток со снимком, заменой и удалением уровня даёт ожидаемый лучший bid/ask. После разрыва расчёт возобновляется только со свежего снимка. |
| 3. Индикаторы | Реализовать VampIndicator и дисбаланс L1 на одном потоке. Отдельно считать будущие доходности. | Пройдены численные примеры из [спецификации данных](data-and-signals.md). Изменение событий после момента решения не меняет уже вычисленных признаков. |
| 4. Бэктест | Подключить сигналы к стратегии в симуляторе Nautilus Trader. Реализовать задержку, исполнение по глубине, учёт позиции и комиссии. | Проверены вручную сделка с несколькими уровнями и сделка на неподвижном стакане. Повтор дня даёт одинаковые сигналы, сделки и итоговый баланс. |

| 6. Проверка переносимости | При положительном результате повторить замороженный эксперимент на новом периоде. ## Вычислительные ресурсы

Ориентир для месячного исследования — Linux, 8 vCPU, 32 ГБ RAM и 500 ГБ NVMe; это оценка до замеров. Обрабатывать файлы последовательно, сохраняя компактные признаки и сделки. По пробному дню оценить диск как сумму всех сохраняемых суточных архивов и результатов плюс пиковое место для распаковки. Измерить также активный торговый день. Время обработки и пиковая память определяют допустимое число параллельных прогонов. GPU для этапов 1–5 не требуется.

## Последующие исследования

- **Адаптивная глубина.** Сначала сравнить фиксированный Q с долей доступной глубины. Для MLQAdapter подавать только уже полученные признаки волатильности, глубины, спреда и потока. Для дисбаланса агрессивных сделок подключить отдельную ленту сделок. Выход — один Q из проверенной сетки. Обучать на ранних днях, выбирать модель на валидации, сравнивать с обоими простыми правилами на новом периоде по IC и чистому результату.
- **Межбиржевое опережение.** CrossExchangeMonitor принимает два потока сопоставимых спотовых инструментов. Соединять последние известные состояния по времени получения, проверив сопоставимость часов записи и исключая устаревшие котировки. Сравнить локальный прогноз с прогнозом, использующим ведущую площадку, при задержке исполнения ведомой. Сделка на одной площадке несёт направленный риск. Для отдельного теста двухстороннего арбитража потребуются балансы на обеих биржах, модель исполнения обеих ног и учёт незахеджированного остатка.
- **Composite VAMP.** После проверки синхронизации привести цены и объёмы к общим единицам, измерить чувствительность к исключению каждой площадки. Глобальную глубину использовать как признак; исполнение считать только по ликвидности выбранной площадки.
